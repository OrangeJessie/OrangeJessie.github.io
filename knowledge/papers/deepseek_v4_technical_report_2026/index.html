DeepSeek-V4 1M Context MoE + Hybrid Attention 2026 Technical Report

DeepSeek-V4 技术报告精读

这份报告的主线不是“又大又强”，而是把长上下文推到工程上可常态使用：用混合压缩注意力降低 1M token 推理成本，用 mHC 和 Muon 稳定超大 MoE 训练，再用 specialist + OPD 把多个能力专家合成一个统一模型。

TL;DR

V4-Pro：1.6T total / 49B activated，目标是开源模型上限，支持 Non-think、High、Max 三档 reasoning effort。

V4-Flash：284B total / 13B activated，目标是成本效率；在更大 thinking budget 下，推理任务接近 Pro。

架构核心：CSA 负责“压缩后再稀疏选择”，HCA 负责“更猛烈压缩但保持 dense attention”，两者交错使用，让 1M context 的 FLOPs 和 KV cache 都大幅下降。

训练核心：Muon 不是简单替换 AdamW；V4 还需要 mHC、FP4 QAT、anticipatory routing、SwiGLU clamping 和一整套确定性/容错基础设施托住训练。

后训练核心：先训练数学、代码、agent、instruction 等 specialist，再用 full-vocabulary OPD 做统一模型合并，避免传统 weight merge 或 mixed RL 的能力互相冲掉。

报告定位

本文按官方 PDF 和 Hugging Face model card 整理。闭源模型对比、内部 Codeforces/R&D/白领任务评测均为 DeepSeek 官方报告中的作者结果，未独立复现。

01方法机制

整体架构：DeepSeek-V3 路线的长上下文版本

V4 不是从零换架构。它保留 DeepSeekMoE 和 MTP，把 attention、residual、optimizer 和系统实现同时升级。这样做的好处是主能力栈延续，风险集中在长上下文瓶颈和训练稳定性上。

组件V4 做法解决的问题
MoE: Mixture-of-Experts每个 token 只激活部分专家，因此 total parameters 很大，但 activated parameters 可控。V4-Pro 是 1.6T total、49B activated；V4-Flash 是 284B total、13B activated。沿用 DeepSeekMoE，所有 Transformer block 使用 MoE；前 3 个 MoE 层用 Hash routing: static token-id to expert-id routing浅层 MoE 的专家集合不完全靠 learned router 临时选择，而是用 checkpoint 中固定的 token-id -> expert-id 查表来决定候选专家；learned gate 仍会给这些专家打分加权。V4 只在前 3 个 bootstrap MoE 层使用。。MoE 解决“模型容量 vs 每 token 计算量”的矛盾：总参数可变大，但单个 token 只激活少量专家。Hash routing 给浅层一个稳定的 routing bootstrap，降低早期表征还弱时的路由抖动。
MTP: Multi-Token Prediction训练时不只预测下一个 token，也预测未来 token。V4 沿用 V3 配置，MTP depth=1，训练中大部分阶段 loss weight=0.3，学习率衰减阶段降为 0.1。沿用 DeepSeek-V3 的 MTP modules 和 objective。提升 token-level 表征和推理吞吐相关能力。
AttentionHybrid CSA/HCA，前两层 Flash 用 pure SWA；Pro 前两层用 HCA；后续 CSA/HCA 交错。让 1M context 不被 attention FLOPs 和 KV cache 拖死。
Residual加入 mHC，把 residual stream 扩成多个 channel，并约束 residual mixing。提高深层信号传播能力，同时控制数值不炸。
Optimizer大部分模块用 Muon；embedding、prediction head、RMSNorm、mHC 静态 bias/gate 仍用 AdamW。更快收敛和更稳定的大规模训练。

Hybrid Attention：CSA 管选择，HCA 管极限压缩

1M token 的核心成本来自 attention：每生成一个 token，都要看很长的历史。V4 的答案不是单一 sparse attention，而是把两种压缩注意力交错使用。

机制链路

CSA: Compressed Sparse Attention先用 learned compressor 把历史 KV 压短，再用轻量相关性打分器对每个 query 选 top-k compressed entries 做 attention。V4 的 c4a 输出长度约为原来的 1/4，但每个 compressed entry 来自一个带学习权重的局部窗口，不是简单平均。

CSA 先把历史 KV 沿 sequence dimension 压缩：V4 中 m=4，所以 1M 历史先变成约 250K 个 compressed KV entry。

这里的压缩不是删除 3/4 token，也不是固定 average pooling。对 c4a，第 j 个 compressed token 是原始位置 [4j-4, 4j+3] 这 8 个 token 的 Softmax-gated weighted pooling压缩器先给窗口内 token 计算 gate logits，加上 learned positional bias 后做 softmax，得到归一化权重；compressed KV 是窗口内 KV 的加权和。权重由模型学习，所以可以偏向更有用的位置。；窗口每次滑动 4 个 token，因此整体数量约变成 n/4。

但 250K 仍然太多，于是 CSA 再用 Lightning Indexer: cheap top-k selector一个轻量级相关性打分器：把当前 query 和每个 compressed KV entry 投到较小的 indexer 空间，用 ReLU-scored multi-head dot product 估计相关性，再保留分数最高的 top-k entries。它负责候选召回，不是最终 attention。 给每个 query 选 top-k。Flash 的 top-k 是 512，Pro 是 1024。也就是说，每个 token 不再扫全历史，而是扫“压缩后的少量相关块”。

关键区别是：indexer 的 top-k 分数只决定“哪些 compressed entries 值得拿进来”；拿进来之后，核心 attention 仍会用正常的 query/key/value 在这些 entries 上重新计算 softmax attention。可以把它理解成检索系统里的“先召回候选，再精排”。

为避免压缩块内部和最近 token 细节丢失，CSA 额外拼一个 sliding window attention 分支，V4 中窗口为 128 token。

HCA: Heavily Compressed Attention把每 m′ 个 token 的 KV 压成一个 entry，m′ 远大于 m；V4 中 m′=128。它不做 top-k sparse selection，而是在更少的 compressed entries 上保持 dense attention。

HCA 更激进：V4 中 m′=128，1M 历史约变成 7812 个 compressed KV entry。

HCA 不再额外做 sparse top-k。直觉是压缩已经很强，候选数足够小，可以保留 dense attention，减少 indexer 选择带来的复杂性。

CSA 像“先压缩再找相关块”，HCA 像“压得很狠后全看”。两者交错，是在细粒度检索能力和极限内存/算力压缩之间做混合。

效率数字

官方报告称，在 1M-token context 下，V4-Pro 只需要 DeepSeek-V3.2 的 27% single-token inference FLOPs 和 10% KV cache；V4-Flash 则是 10% FLOPs 和 7% KV cache。

如果拿常见 BF16 GQA8、head dimension 128 当 baseline，V4 的 KV cache 在 1M context 下约降到该 baseline 的 2%。这个数字很激进，关键依赖压缩 KV、FP8/BF16 混合存储、FP4 indexer 和专门 cache layout。

mHC：多条 residual 通道 + 受控混合

这节可以先不要看公式。普通 Transformer 的 Residual streamTransformer 层与层之间传递的主 hidden state。每个 attention/MLP block 都先读这条状态，算出一个更新量，再把更新量加回去：x_{l+1}=x_l+F_l(x_l)。它像模型的工作记忆主干道，承载前面 token、前面层已经积累的信息。 像一条主干道：每层都在同一个 hidden state 上加一段更新。mHC 的想法是把这条主干道拆成多条 residual channel，让不同层可以从不同通道读信息、再把新信息写回这些通道。

问题也随之出现：通道变多以后，如果每层都能随便放大、相减、重混这些通道，几百层叠起来后信号可能被越混越大，或者被互相抵消。mHC 里的 “manifold-constrained” 就是在限制这种混合：可以换道和重分配，但不能把 residual 信息任意放大或乱消掉。

$$X_{l+1}=B_lX_l+C_lF_l(A_lX_l)$$

把公式拆开看

X_l

不再是一条 residual stream，而是多条 residual channels。可以把它理解成模型在每一层都保留了几条并行的“记忆轨道”。

A_lX_l

A_l 决定当前 Transformer block 要从这些通道里读哪种组合。比如某层可以主要读通道 1，同时少量参考通道 2/3。

C_lF_l(...)

F_l 是这一层真正做 attention/MLP 后得到的新信息，C_l 决定这些新信息写回哪些 residual channels。

B_lX_l

B_l 决定旧 residual channels 怎么传到下一层。mHC 最关键的约束就在这里：B_l 不是任意矩阵，而是被投影到 doubly stochastic matrix manifold，也就是 Birkhoff polytope。

直觉上，doubly stochastic matrix 像“带权重的换道规则”：每条旧通道的信息可以分配到新通道，但权重非负、行列和受控，所以它更像重新分配，不像随便乘 3 倍或拿一条通道去减另一条通道。

mHC: Manifold-Constrained Hyper-Connections把 residual stream 扩成多条 channel，并学习输入映射 A、旧通道混合 B、输出写回 C；其中 B 被限制在 doubly stochastic matrix manifold 上，让旧 residual 信息只能稳定重分配，不能被任意放大或抵消。 解决的是“深层 residual 信号怎么传得更丰富但仍稳定”。宽 residual 带来更多路径，B_l 的约束让这些路径的旧信息传播满足 ||B_l||_2 ≤ 1，因此 residual transformation 是 non-expansive：层数加深时，旧信号不容易被一层层放大到失控。

报告还把 A_l 和 C_l 约束为非负且有界，进一步避免 signal cancellation。对 V4 来说，mHC 不是简单“加宽 hidden size”，而是增加 residual 路径数量，并给路径之间的读、写、传递都加稳定规则。

Muon：不是 AdamW everywhere，而是矩阵更新几何

V4 把大部分模块交给 Muon，但保留 AdamW 处理 embedding、prediction head、RMSNorm 和 mHC 的部分参数。这说明 Muon 是主力优化器，不是无脑全替换。

AdamW 视角

AdamW 把一个权重矩阵 W 当成很多独立标量参数。它为每个元素 w_ij 维护一阶、二阶动量，再按 m_ij / sqrt(v_ij) 更新。

这很稳，但它不显式关心 W 作为线性层的几何含义：行对应输出方向，列对应输入方向，整个更新 ΔW 本身也是一个矩阵变换。

Muon 视角

Muon optimizerMomentUm Orthogonalized by Newton-Schulz。面向 hidden layer 的二维矩阵参数；先做 momentum / Nesterov update，再把更新矩阵近似正交化，最后按 RMS rescaling 和 weight decay 更新参数。 先像 SGD-momentum 一样得到一个更新矩阵 M，然后不直接用 M 更新，而是看它的矩阵形状。如果 M = UΣV^T，Σ 代表各个输入-输出耦合方向上的更新强度。

Transformer 里很多矩阵梯度会接近低秩：少数 singular direction 很大，大量方向很小。Muon 的做法是保留方向 U,V，把奇异值压到接近 1，也就是把 M 换成近似 UV^T。这叫更新矩阵正交化。

所以“矩阵更新几何”的意思是：Muon 不是逐元素判断哪个坐标该大该小，而是把一次更新看成线性变换，先让这个变换在不同方向上更均衡、更少病态，再落到参数上。

Newton-Schulz 做什么

真正算 M = UΣV^T 的 SVD 太慢，所以 Muon 用 Newton-Schulz 迭代近似得到 UV^T。先把 M 归一化，再反复做多项式矩阵迭代 X ← aX + b(XX^T)X + c(XX^T)^2X。

从奇异值角度看，这个迭代把 σ 变成 aσ + bσ^3 + cσ^5，多次迭代后把不同大小的 singular values 推近 1。V4 使用 10 次 hybrid Newton-Schulz：前 8 步快速靠近 1，后 2 步稳定到 1。

为什么不是 everywhere

Muon 的假设是参数天然是二维 hidden weight matrix，适合谈“输入方向到输出方向”的矩阵更新几何。embedding 表、prediction head、RMSNorm、bias、gate 这类参数要么是 lookup/输出语义特殊，要么是一维/标量参数，不适合硬套矩阵正交更新。

所以 V4 的配置是混合优化：大部分 hidden matrices 用 Muon；embedding、prediction head、RMSNorm、mHC 静态 bias/gate 仍用 AdamW。它与 V4 attention 也配合：CSA/HCA 可直接对 query 和 compressed KV entry 做 RMSNorm，因此报告称不需要 QK-Clip 来压 attention logits。

训练稳定性：MoE routing 是 spike 入口

Anticipatory Routing

报告认为 loss spike 与 MoE outliers 和 routing 机制相关。V4 的做法是在 step t 使用当前参数做 feature computation，但 routing indices 来自历史参数 θ_{t-Δt}。

这样 routing 网络不再和 backbone 同步剧烈变化，能打断“routing 导致 outlier，outlier 又放大 routing 偏移”的循环。工程上它通过提前取 step t 的数据并预计算 routing indices，额外 wall-clock 控制在约 20%；只在 loss spike 触发后短期启用，整体开销很小。

SwiGLU Clamping

V4 对 SwiGLU 的 linear component clamp 到 [-10, 10]，gate component 上界设为 10。这是直接抑制异常值的工程手段。

报告坦率说，这两招的理论机制还不充分；它们是实证有效的 training-stability recipe。

后训练：specialist → OPD 合并

V4 把 DeepSeek-V3.2 的 mixed RL 阶段完全替换为 On-Policy Distillation。主线可以拆成两步：先把数学、代码、agent、instruction following 等方向各自训练成 specialist；再让一个统一 student 在自己生成的 trajectories 上，对齐这些 specialists 的 full-vocabulary logits。

阶段输入信号训练目标产物
Domain SFT高质量、领域特定的 SFT 数据让 base model 先学会该领域的基本格式、知识和解题风格每个领域的初始 specialist

OPD 合并student 自己采样出的 trajectories + 对应 teacher 的 logits最小化 student 分布到 teacher 分布的 reverse KL，把多个物理上独立的专家能力压回一个参数空间最终统一 DeepSeek-V4 model
Specialist Training

数学、代码、agent、instruction following 等目标域不是混在一起直接训。每个领域都先从同一个 base 出发，走一轮领域 SFT，再走一轮领域 RL。这样每个 expert 的 reward、prompt 格式、上下文长度、工具环境都可以按该领域单独设计。

RL 算法是 GRPO: Group Relative Policy OptimizationDeepSeek-R1 使用的 value-free RL 算法。对同一 prompt 采多条 response，用组内相对 reward 构造 advantage，避免训练 value model。。对 easy-to-verify 任务，reward 可以来自规则、测试用例或 verifier；对 agent / instruction 这类不容易自动验真的任务，V4 引入 GRM 来做轨迹评价。

三档 reasoning mode 也在 specialist 阶段被拆开训练：Non-think、Think High、Think Max 使用不同 length penalty 和 context window。Think Max 还会在 system prompt 注入“absolute maximum reasoning effort”指令，所以它不是推理时简单把 max_tokens 开大，而是后训练时就学了更长、更彻底的思考分布。

这一步的代价是能力被分散在多个物理 checkpoint 里：math expert 很会数学，code expert 很会代码，agent expert 会工具和环境交互，但不能直接把这些 checkpoint 端给用户，也不能简单平均权重。

Thinking management

V4 对 thinking trace 的处理分两类。带工具调用时，完整 reasoning history 会跨 tool result、tool call，甚至跨 user message boundary 保留；普通多轮对话则沿用旧策略：新用户消息到来时丢弃上一轮 reasoning content，只保留可见对话。

这件事看似是 prompt 格式，实际影响后训练数据构造。agent specialist 的轨迹要保留中间思考、工具调用和工具结果，让模型学会长程任务状态；聊天 specialist 则要避免把旧 thinking 变成下一轮可见输入，防止普通对话被不必要的历史思考拖长。

GRM: Generative Reward Model让模型生成带 rubric 的评估/打分，而不是输出一个标量 reward。V4 还对 GRM 本身做 RL，使 actor 同时学习生成能力和 judging 能力。

对 hard-to-verify 任务，V4 不再依赖传统 scalar reward model。传统 reward model 通常直接输出一个分数，训练它需要大量人工偏好或打分数据；而 GRM 是让模型按 rubric 生成评价过程和判断。

DeepSeek 的说法是，actor network 本身也作为 GRM 被 RL 优化，因此模型既学“怎么生成答案”，也学“怎么判断答案”。这让 judging 能力和 reasoning 能力绑定在一起，适合 agent、长写作、复杂 instruction following 这类没有明确单元测试的任务。

在 specialist 阶段，GRM 提供的是领域内 RL 的 reward 信号；到了 OPD 阶段，GRM 本身训练出来的能力会作为某些 teacher 的行为分布，被蒸馏进统一 student。

OPD: On-Policy Distillation学生模型在自己生成的 trajectories 上学习多个 teacher/specialist 的输出分布。V4 使用 reverse KL，把多个物理上独立的专家能力合并到统一参数空间。

OPD 的关键不是“拿专家答案做 SFT”。SFT 只告诉 student 某个 token 是正确示范；OPD 则让 teacher 在 student 当前走到的每一个前缀上，给出整个 vocabulary 的概率分布。student 学的是 teacher 对所有候选 token 的相对偏好。

“On-policy” 的意思是训练前缀来自 student 自己，而不是固定离线数据。流程是：student 先按当前策略生成一条 trajectory；系统判断这条样本应由哪些 teacher 提供信号；teacher 在同一上下文前缀上 forward，输出 logits；student 用 KL loss 把自己的分布往 teacher 分布贴近。

官方目标可以写成：

$$L_{OPD}(\theta)=\sum_{i=1}^{N} w_i \cdot D_{KL}(\pi_\theta \Vert \pi_{E_i})$$

更展开地看，在每个 token 位置上，student 的分布是 πθ(· | x, y<t)，teacher 的分布是 πEi(· | x, y<t)。reverse KL 会惩罚 student 把概率放到 teacher 认为很差的 token 上；如果当前样本是数学题，数学 teacher 的 logits 会更有权重，如果是代码题，代码 teacher 更相关。

这比 weight merge 更稳：weight merge 是直接混参数，两个 expert 的 internal representation 可能不对齐；mixed RL 是在一个模型里同时吃多个 reward，reward 之间可能互相拉扯。OPD 让 expert 保持独立强能力，再通过 logits-level alignment 把行为压进一个 student。

Full-vocabulary KL

很多 OPD/蒸馏实现会偷懒：只看 student 实际采样出来的 token，在这个 token 上估一个 KL 或 advantage。这很省显存和算力，但梯度方差大，因为一次只观察到 vocabulary 里的一个点。

V4 选择 full-vocabulary logit distillation：对每个位置保留完整 vocabulary 分布来算精确 KL。这样 student 不只知道“当前 token 应该更像 teacher”，还知道 teacher 认为哪些替代 token 也可接受、哪些 token 明显不该选。

代价是工程很重：词表超过 100K，十多个 teacher 都吐 full logits 会爆内存。V4 的做法是不落盘完整 logits，而是缓存 teacher 最后一层 hidden states；训练时按 teacher index 排 batch，只加载一个 teacher prediction head，把 hidden states 临时还原成 logits，再用 TileLang kernel 计算精确 KL。

所以这节真正的工程点是：OPD 不是一个小 loss trick，而是一整套多 teacher 调度、hidden-state cache、prediction-head 按需加载、rollout 容错和长上下文数据管线。

系统基础设施：让 1M context 真能跑起来

系统点机制为什么重要
FP4 QATQAT: Quantization-Aware Training训练时模拟量化误差，让模型适应低精度部署。V4 对 MoE expert weights 和 CSA indexer QK path 做 FP4 QAT。；推理/rollout 阶段直接用真实 FP4 quantized weights。降低 memory loading 和采样延迟，并让 rollout 行为与线上部署一致。
KV cache layoutKV cache: Key-Value Cache自回归解码时保存历史 token 的 key/value，避免每生成一个 token 都重新计算完整历史。V4 因 CSA/HCA/SWA 混合，KV cache 类型和更新规则不一致，需要自定义布局。 拆为 classical KV cache 和 state cache；SWA 与未压缩 tail tokens 放 state cache。标准 PagedAttention 假设不再成立，必须为混合注意力重新设计 cache 管理。
On-disk KVCSA/HCA compressed KV 直接落盘；SWA 提供 full caching、periodic checkpointing、zero caching 三种策略。共享 prefix 请求可跳过重复 prefill，在长上下文服务里非常值钱。
Rollout WALWAL: Write-Ahead Log每生成一个 token 就立即写入日志。训练/rollout 任务被抢占或故障后，可用已生成 token 和保存的 KV cache 继续解码，而不是从头重采样。 token-granular 持久化。从头重采样会产生 length bias：短 response 更容易幸存，长 response 更容易被中断重来。
DSec SandboxFunction call、container、microVM、fullVM 四种 substrate 统一 API。agentic post-training/eval 需要可复现、可抢占、可高并发的执行环境。

功能写作对 Gemini-3.1-Pro：DeepSeek-V4-Pro 总体 win rate 62.65%，Gemini 34.10%。创意写作中，instruction following 为 60.03% vs 39.44%，writing quality 为 77.48% vs 22.35%。

但复杂指令和多轮写作对 Claude Opus 4.5 仍落后：45.9% vs 52.0%。

Search

RAG: Retrieval-Augmented Generation先检索相关资料，再把检索结果放进上下文生成答案。V4 报告中 Non-think 模式使用 RAG，thinking 模式使用 agentic search。 对 V3.2：V4-Pro 总体 win 28.1%、V3.2 win 10.4%、tie 61.5%。Agentic search 对 RAG：agent win 61.7%、RAG win 18.3%。

Agentic search 平均 16.2 tool calls，prefill 13649 tokens、output 1526 tokens；RAG 是 10453 / 1308。

Code Agent

内部 R&D coding benchmark：DeepSeek-V4-Pro-Max pass rate 67%，接近 Opus 4.5 的 70%，低于 Opus 4.6 Thinking 的 80%。

开发者调查中，52% 认为可作为默认主力 coding model，39% 倾向 yes，少于 9% no；主要问题是小错误、误解模糊 prompt、偶发过度思考。

04限制与复现风险

论文自己承认的问题

  • 架构复杂：为降低风险保留了很多预验证组件和 tricks，未来需要更 principled 地蒸馏核心设计。
  • Anticipatory Routing 和 SwiGLU Clamping 机制未完全理解，目前是经验稳定技巧。
  • 复杂中文多轮/强约束写作仍落后 Opus 4.5；Formatting Aesthetics 也有提升空间。
  • 长上下文 MRCR 超过 128K 后仍有退化，1M 支持不是“无损长上下文”。

工程复现风险

  • 论文没有公开完整训练数据配比、硬件规模、训练成本和全部后训练数据。
  • CSA/HCA 的收益依赖 kernel、cache layout、context parallelism、FP4/FP8 路径一起工作，单独复刻算法公式不等于复现性能。
  • Full-vocabulary OPD 对 teacher scheduling、hidden-state cache、prediction head 载入/卸载要求很高，小团队直接照搬成本很重。
  • 内部评测如 Codeforces、R&D coding、白领任务、搜索问答不可完全外部复现，只能作为作者报告证据。

落地建议

如果你关心先读哪块工程启发
长上下文 servingHybrid CSA/HCA、KV cache layout、on-disk KV长上下文效率不是只换 attention；cache 管理和 prefix reuse 是同等重要的系统问题。
大 MoE 训练稳定性mHC、Muon、Anticipatory Routing、SwiGLU Clamping稳定训练需要同时控制 residual、optimizer update、routing 和 activation outlier。
后训练合并Specialist Training、GRM、OPD先让专家在各自 reward 下变强，再用 full-vocab reverse KL 合并，比直接混合 RL 更可控。
Agentic AIInterleaved thinking、DSML tool schema、DSec sandbox、rollout WAL模型能力和 agent runtime 是一体设计；工具协议、上下文管理、沙箱复现都会影响最终效果。
