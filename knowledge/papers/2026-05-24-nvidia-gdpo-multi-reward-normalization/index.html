GDPO: Group reward-Decoupled Normalization Policy Optimization for Multi-reward RL Optimization

GDPO 的核心不是重新设计 reward，而是把多 reward 进入 GRPO advantage 的归一化顺序改对：先按 reward 维度在 prompt group 内分别归一化，再按权重聚合，最后做 batch-wise advantage normalization。这个小改动保留了 reward 组合差异，避免多目标训练信号被过早压成同一个标量。

TL;DR

问题：multi-reward GRPO 通常先把 correct、format、length、bug 等 reward 加总，再 group-normalize；不同 reward combination 会被压成相同 advantage，训练信号分辨率下降。

方法：GDPO 对每个 reward 先单独 group-wise normalization，再按权重聚合，并对最终 advantage 做 batch-wise normalization，保持 reward 数增加时的数值尺度稳定。

结果：tool calling、math reasoning、coding reasoning 三类任务中，GDPO 通常比 GRPO 有更高主指标，并更好保持 format、length、bug 等约束。

工程判断：如果现有 GRPO pipeline 是 reward = w1*r1 + w2*r2 后直接归一化，GDPO 应作为第一优先级替换 baseline。

01

问题背景

GDPO 处理的是“多 reward 进入 GRPO 后如何构造 advantage”的问题，不是单纯 reward design 或调权问题。

GRPO 的默认做法

先把同一 response 的多个 reward 加权求和，再在同一个 prompt 的 rollout group 内计算 mean/std advantage。

隐藏损失

sum reward 只保留标量总分，丢掉“同时满足哪些目标”的组合结构。

训练后果

advantage 分辨率降低，格式、长度、正确性等目标可能互相压制，甚至早期训练失败。

Original Figure 2 · reward combination collapsepaper screenshot · p.4
论文 Figure 2：在 two-binary-reward、two-rollout 例子中，GRPO 把六种 reward combination 压成两个 advantage group；GDPO 分 reward 归一化后保留三个 group。
图解读：这个图是 GDPO 的核心动机。GRPO 看总分排序，GDPO 看每个 reward 维度的组内相对位置。因此 (0, 2) 这种“一个 rollout 同时满足两个目标”的情况，不会和 (0, 1) 这种“只满足一个目标”的情况完全混在一起。

不要把 GDPO 简化成“去掉 std”

论文还比较了 GRPO w/o std。去掉标准差确实稍微增加 distinct advantage groups，但实验中 tool calling 的 correct format 直接掉到 0%，说明“删 std”不是可靠修复。

02

方法机制

GDPO 只改 advantage 构造，policy objective、ratio clipping、KL 等主体仍可沿用 GRPO / PPO-style pipeline。

机制拆解

标准 multi-reward GRPO

对第 i 个问题的第 j 条 response，先把 n 个 reward 聚合成 r_sum。这个步骤已经把 reward vector 压成单个 scalar。

随后在同一 prompt 的 G 个 rollouts 内对 r_sum 做 group-wise mean/std normalization，得到 A_sum。

GDPO decoupled normalization

GDPO 对每个 reward k 分别计算 group-wise normalized advantage。也就是说，每个 reward 先独立表达“这条 response 在本目标下相对同组其他 response 好不好”。

这些 per-reward advantage 再按 reward weight 聚合，所以最终 update 仍是一条标量 advantage，但它保留了每个 reward 维度的相对排序。

Batch-wise advantage normalization

per-reward advantage 加总后，reward 数越多，数值尺度可能越大。GDPO 在 batch 级再做 mean/std normalization，让最终 advantage 的尺度不随 reward 个数线性膨胀。

Appendix A 显示，去掉这一步时 GDPO w/o BN 有时无法收敛，因此 batch normalization 是稳定性组件，不只是 cosmetic normalization。

Priority variation

当 reward 难度不同，简单调 weight 不一定能表达优先级。论文在 math 中把 length reward 改成 conditioned length reward：只有 correctness 满足时才给 length reward。

这个做法把“主目标先达成，辅助目标再介入”的层级写进 reward function，比单纯降低 length weight 更可控。

GRPO 的归一化顺序

标准 multi-reward GRPO：先聚合 reward，再做 group normalization。

$$r_{\mathrm{sum}}^{(i,j)} = r_1^{(i,j)} + \cdots + r_n^{(i,j)}, \qquad A_{\mathrm{sum}}^{(i,j)} = \frac{r_{\mathrm{sum}}^{(i,j)} - \mathrm{mean}\{r_{\mathrm{sum}}^{(i,1)},\ldots,r_{\mathrm{sum}}^{(i,G)}\}}{\mathrm{std}\{r_{\mathrm{sum}}^{(i,1)},\ldots,r_{\mathrm{sum}}^{(i,G)}\}}$$
GDPO 的 per-reward normalization

GDPO：每个 reward 维度先独立 group-normalize，再按权重聚合。

$$A_k^{(i,j)} = \frac{r_k^{(i,j)} - \mathrm{mean}\{r_k^{(i,1)},\ldots,r_k^{(i,G)}\}}{\mathrm{std}\{r_k^{(i,1)},\ldots,r_k^{(i,G)}\}}, \quad A_{\mathrm{sum}}^{(i,j)} = \sum_{k=1}^{n} w_k A_k^{(i,j)}$$
Batch-wise advantage normalization

最终用于 policy update 的 advantage；分母里的 epsilon 是数值稳定项。

$$\hat{A}_{\mathrm{sum}}^{(i,j)} = \frac{A_{\mathrm{sum}}^{(i,j)} - \mathrm{mean}\{A_{\mathrm{sum}}^{(i',j')}\mid i'\in D_{\mathrm{Batch}}, j'=1,\ldots,G\}}{\mathrm{std}\{A_{\mathrm{sum}}^{(i',j')}\mid i'\in D_{\mathrm{Batch}}, j'=1,\ldots,G\}+\epsilon}$$

实现细节

GDPO 的工程改动很集中：保存 reward vector、逐 reward 归一化、聚合、batch-wise normalize。

落地清单

最小替换点

在 GRPO trainer 里不要只保留 rewards scalar；需要保留 rewards_per_func 或等价 reward matrix，形状近似为 [batch * G, num_rewards]。

按 reward 维度循环，view 成 [batch, G] 后计算每个 prompt group 的 mean/std，再 repeat 回 rollout 维度。

把所有 reward 的 normalized advantage stack 起来，乘 reward_weights 后求和。

对聚合后的 advantage 做 batch mean/std normalization，再进入原 GRPO clipped loss。

需要保留的监控

每个 reward 的 raw mean/std、稀疏率、normalized advantage 分布。

每个 reward advantage 与最终 advantage 的相关性，避免某个 reward 长期被权重或方差吞掉。

distinct advantage groups 或 advantage entropy，用来观察信号是否被压缩。

主指标和约束指标分开画，不能只看 weighted total reward。

何时用 conditioned reward

当一个 reward 是 hard/primary，例如 correctness、pass rate，另一个是 easy/auxiliary，例如 length、format、style，优先考虑让辅助 reward conditioned on 主 reward。

conditioned reward 会更强地表达层级，适合主从目标明确的业务；若目标本身是平权 Pareto 偏好，就不应随便条件化。

复现提醒

GDPO 是 drop-in replacement for advantage computation，不是完整训练 recipe。math 实验仍结合了 DLER/DAPO 风格设置：dynamic sampling、higher clipping thresholds、token-mean loss。

05

边界与风险

GDPO 解决的是 multi-reward GRPO 的训练信号压缩；它不是万能多目标优化器。

不是 Pareto optimizer

最终仍是加权 scalar advantage，不直接学习 Pareto front 或可控偏好方向。

reward 质量仍是上限

如果 correctness parser、format checker 或 bug detector 可被 hack，GDPO 会更稳定地学到错误激励。

需要 reward 层级判断

conditioned reward 很实用，但要求你知道哪个目标是 primary；平权偏好场景不宜硬条件化。

规模验证有限

公开实验覆盖 1.5B、3B、4B、7B；30B+ 与复杂 agent 环境仍需本地验证。

结论

我的工程判断：如果你的 GRPO 训练已经有多个 reward，且目前做法是先加权求和再 normalize，那么 GDPO 值得作为第一版替换 baseline。它改动小、诊断清晰、失败模式也比“删 std”更可控。

上线前必须做 per-reward dashboard；只看 total reward 会把 GDPO 最想保护的 reward 维度差异重新遮住。
